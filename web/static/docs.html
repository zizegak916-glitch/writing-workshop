Product guide · 2026-07-29

从打开页面，到完成一次安全写作。

这份文档不假设你已经懂 API、Docker 或 Skill。先选择你的使用方式，再按一条完整路线跑通。

先理解：Pages 在线版与后端增强模式

GitHub Pages · 正式在线版

这是项目当前对外发布的真实 HTTPS 站点，不是临时预览。可以建立浏览器本地项目、编辑、导入导出，并使用保存在当前浏览器中的 BYOK 自定义 API。目标接口必须允许此 Pages 域名跨域访问。

后端增强模式

运行仓库自带的 Go 服务，或部署兼容后端后，可增加密钥保管、Skill 执行、SSE 流式输出、中断和后端项目导入。浏览器不会把每次编辑静默镜像到后端。

托管方式不等于功能真假：Pages 的浏览器 BYOK 可直接发起模型请求；默认工作流未同时部署 Go API，所以后端 Skill、项目同步和 SSE 仍不可用。GitHub Pages 与 OpenAI Sites 是独立托管方式。

60 秒启动

路线 0：直接使用 Pages 在线版

打开 Writing Workshop 工作台，新建项目即可编辑。无需安装 Go 或 Docker。由于项目数据属于当前 github.io 域名的浏览器存储，请定期使用顶部导出或项目操作台下载备份。

路线 A：Docker（最省事）

需要安装 Git 与 Docker Desktop。复制下面四行命令：

git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
docker compose up --build

# 浏览器打开
http://127.0.0.1:8080/app.html

第一次会以无密钥 Demo 模式启动。看到工作台后，打开 能力后台配置模型；也可以先不配，验证本地项目和内置能力链路。

路线 B：直接运行源码

需要 Go 1.25 或更高版本：

git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
go build -o writing-workshop ./cmd/writing-workshop
./writing-workshop serve --demo --port 8080

默认只监听 127.0.0.1，这是为了避免把作品与密钥意外暴露到局域网。如确实需要容器或局域网访问，再显式加 --host 0.0.0.0，并自行配置反向代理鉴权。

确认服务健康

curl http://127.0.0.1:8080/api/health
# 预期：{"mode":"demo","status":"ok"}

建立第一个项目

点击顶部 ＋填写项目名称添加第一章建立人物卡/笔记开始写作
  1. 在工作台顶部点击 ＋，填写项目名、题材与简介；已有自定义分类时可同时多选分类。
  2. 左侧切到“章节”，点击“添加章节”，输入标题。
  3. 切到“人物”，录入姓名、定位、描述与角色弧线；临时考据、场景材料和会议记录可放到“笔记”。
  4. 在中间编辑区写作。自动保存开启时，数据写入浏览器 IndexedDB；点击顶部保存可以立即保存。
  5. 第一次重要编辑后，点击顶部下载图标导出项目备份。项目包版本 4 包含项目、章节、大纲、人物、笔记、记忆、自定义分类与 Prompt Skill。
本地优先：Pages 正式在线版与后端增强模式都可以使用浏览器数据库。清除浏览器站点数据会删除这部分内容，因此长期项目务必定期导出。

工作台各区域做什么

区域用途常用操作
顶部栏项目切换、统计、全局设置新建、后台、设置、导出、保存
左侧资料栏项目结构与设定大纲、章节、人物、笔记
中央编辑区唯一正文工作面格式、专注、预览、快速 AI、导出
右侧 AI 区任务、上下文预算与候选助手、对比、记忆、历史、流程；固定请求栏显示本次预算
能力后台服务端配置与调试Provider、URL、Key、项目、规则、Skill、公开能力目录、API 测试

桌面端右侧的能力目录独立滚动，底部“补充指令 / 上下文预算 / 开始生成”请求栏保持可见；切换到对比、记忆、历史或流程时会隐藏，返回“助手”后恢复。手机端会把资料栏和 AI 区折叠到底部导航，预算卡随 AI 内容正常滚动，避免挡住底部导航。正文仍是默认首屏，不会把桌面三栏硬挤进窄屏。

项目操作台

点击顶部项目名进入“我的项目”。搜索框会匹配项目名、类型和自定义分类；分类下拉可进一步筛选。每个项目提供重命名、复制、分类、单独导出和删除。删除会明确列出连带删除的大纲、人物、章节、笔记与记忆并再次确认，不提供无确认批量删除。

“分类管理”创建浏览器本地分类并可修改名称、范围和颜色；项目和记忆分类都可自定义。它们保存在当前站点的浏览器存储，不会自动覆盖后台的能力分类。

从自部署后端导入

先用 Docker 或源码启动 Go 后端，再在项目操作台点击“从自部署后端导入”。工作台会读取后端现有项目、章节和人物，建立一个新的浏览器项目副本。之后的浏览器编辑仍保存在 IndexedDB，不会静默覆盖后端资料；需要再次迁移时重新显式导入并核对。

完成一次 AI 写作流程

描述任务选择上下文组合能力生成候选确认写入
  1. 描述这一次任务。例如“检查这段对话的动机断点”，不要写成永久项目规则。
  2. 只选需要的上下文。当前选区/正文、项目设定、大纲、人物卡、项目笔记、记忆都可以单独开关。普通助手的固定请求栏显示估算 token、当前模型上限和百分比；估算不要求先配置 API，模型返回 usage 后才会追加上次实际输入/输出。
  3. 选择功能与 Skill。“模式”里的功能卡决定本次隐形使用哪个浏览器 Prompt Skill；“流程”里还可逐项勾选多个后端 Skill，或一键应用技能包。“已选 N 项”会明确显示后端组合。
  4. 点击生成候选。本地后端通过 POST /api/run 返回 SSE 事件；运行中可以中断。
  5. 检查后再决定去向。候选可复制、替换运行时选区、插入光标或追加到正文。普通、快捷、多模型、降 AI 与递归创作都会绑定生成时文档；跨文档应用会被阻止，替换时还会检查正文是否已变化。
  6. 记忆另行确认。“整理为记忆”只把候选放入记忆编辑框，仍需再次保存；不会和正文写入捆绑。
可恢复：流程历史保留完整候选；发生正文写入时还会记录写入前快照。恢复不会自动保存章节，你仍有最后一次确认机会。

导入、导出与备份

导入单篇内容

在新建/导入入口选择 Markdown、TXT 或 DOCX。先检查解析后的标题与正文，再放入当前项目。

导出当前正文

编辑工具栏的“导出”用于保存正在编辑的章节，适合送审、分享或进入其他排版工具。

导出完整项目

顶部下载按钮或项目操作台“导出”会先保存当前编辑，再打包项目、章节、大纲、人物、笔记、记忆、本项目候选/恢复快照、自定义分类和已修改的 Prompt Skill。长期创作建议每个重要阶段保存一份带日期的 v5 备份。

增量资料

新增资料应按文件 hash 只处理一次；脚本负责去重和分类，AI 只总结新文件，避免每次重读全库。

如果浏览器提示下载被阻止，请允许当前站点下载文件。若导入失败，先确认文件未加密，并用 UTF-8 保存纯文本或 Markdown。一次最多导入 50 个文件；单文件最多 25 MiB、总计最多 100 MiB。v1–v4 项目包会先迁移到 v5 结构，缺少的新字段使用空值，旧记忆、分类和 Prompt Skill 别名会按已知规则保留；高于 v5 的未知版本会被拒绝。v5 导入在一个事务中写入全部项目记录，并重映射历史候选指向的文档 ID；失败时不会留下半个项目。项目备份恢复不会追加 AI 分析结果；普通文本只有在预览页显式开启分析时才会补结构。

浏览器存储不是云盘：工作台会申请持久化存储，并在“我的”页显示占用、配额和是否获批；浏览器仍可能拒绝或在清理站点数据时删除全部内容，所以重要阶段必须导出备份。

配置 API 与模型

Pages 浏览器 BYOK

  1. 打开工作台右上角“设置 → API”，或进入 Pages 的“能力后台 → 模型与 API 配置”。
  2. 常见官方服务可直接选择；中转、自建或本地接口选择“自定义”。已有服务商也可以用 Base URL 覆盖默认地址。
  3. 填写实际模型 ID 与 Base URL。可以填域名、带前缀的 API 根路径，也可以填完整接口地址。
  4. OpenAI 兼容接口保持“自动识别”。其他接口展开“高级网络适配”，选择 OpenAI Responses、Anthropic Messages 或 Ollama /api/chat。
  5. 有 Key 的接口保持“自动”鉴权；无密钥的 Ollama 或局域网服务选“无鉴权”。中转要求额外请求头时填写 JSON，并按网络情况调整超时。
  6. 先点“测试”，成功后保存。配置只跟随当前浏览器的当前域名，不会上传到 GitHub。
405 已处理：Pages 保存与测试不会再 POST 静态 /api/config；只有检测到同源 /api/health 的自部署模式才使用后端配置端点。自定义静态域名也会自动进入浏览器 API 模式。

使用环境变量（更适合长期部署）

export OPENAI_API_KEY="your-key"
./writing-workshop serve --port 8080

OpenRouter 也可使用 OPENROUTER_API_KEY。配置读取接口不会把已保存的完整密钥返回给浏览器。

浏览器直连、CORS 与密钥边界

Pages BYOK 会从浏览器直接请求目标 API。目标接口必须允许当前 Pages origin、请求方法和 Authorization / x-api-key / Content-Type 等实际使用的请求头；这些由目标服务决定，Writing Workshop 不能替第三方服务器放开 CORS。

Pages 工作台浏览器本地配置自定义 API候选返回

自部署模式仍采用同源桥接：浏览器访问自己的 /api/，后端读取密钥并请求模型。这一模式不受模型厂商浏览器 CORS 限制，也更适合长期使用。

不要混淆：把 Key 和自定义请求头存进当前浏览器是用户主动选择的 BYOK；把凭据硬编码进 Pages 文件、仓库 JavaScript、公开环境变量、Issue 或截图仍然是泄露。HTTPS Pages 访问 HTTP 本地接口还可能被浏览器按混合内容拦截。

Prompt Skill 与后端 Skill

管理功能按钮的内置提示词

工作台的 30 个模式卡片以及“实时灵感、资料搜索”两个独立快捷工具，共对应 32 个浏览器 Prompt Skill。点击“润色”“续写”“人物”等功能时，只改变本次请求所用的 Skill；提示词正文不会塞进编辑器，也不会作为聊天内容展示。

  1. 打开工作台右侧 AI 区，切到“流程”。
  2. 在“组合能力”底部找到“内置 Prompt Skill”，点击“查看与修改”。
  3. 按分类或关键词找到功能。左侧“内置”表示使用仓库默认版本，“已修改”表示当前浏览器有覆盖值。
  4. 在右侧改写提示词并保存。下一次点击该功能生成时立即使用新版本，不需要刷新。
  5. 需要撤销时点击“恢复默认”。“导出/导入”可单独备份；完整项目 v5 备份也会携带覆盖值，导入项目时以合并方式恢复。
存储边界：自定义 Prompt Skill 保存在当前域名的 localStorage，不会上传到 GitHub，也不会自动同步到另一台设备、另一个浏览器或另一个域名。清除站点数据前先导出项目或提示词备份。

实际请求按以下顺序组装：内置/自定义 Prompt Skill → 当前选区或正文 → 输出长度与创意要求 → 项目信息和写作记忆 → 额外指令。普通模式、多模型模式、移动端与六个快捷工具都使用同一份浏览器配置。

添加 GitHub 项目或后端 Skill

在能力后台的“能力来源”页添加一项能力。至少填写名称、类型、版本、来源、许可证、入口、执行说明、可见步骤、权限边界和输出类型；分类与标签用于检索，不会增加权限。

{
  "name": "场景节奏检查",
  "type": "skill",
  "category": "revision",
  "tags": ["场景", "节奏"],
  "version": "1.0.0",
  "source": "https://github.com/example/scene-pacing",
  "license": "Apache-2.0",
  "entry": "prompt:scene-pacing",
  "output": "text",
  "steps": ["读取显式上下文", "检查节奏", "返回候选"],
  "permissions": ["context:read"],
  "supports_stream": true,
  "supports_abort": true
}

当前实现会登记、校验和组合能力清单，但不会因为你粘贴 GitHub URL 就执行仓库代码。第三方代码需要明确的沙箱执行器与最小权限机制；这是安全边界，不是缺少一个按钮。

从公开 Agent Skills / MCP 目录登记来源

  1. 必须通过 Docker 或本地 Go 后端打开 admin.html；Pages 默认没有该服务端 API。
  2. 切到“公开能力目录”，先看维护者、许可证、核验日期、所需权限和风险。现行 OpenAI 示例入口是 openai/plugins；旧 openai/skills 已按上游状态标为弃用参考。
  3. “查看上游”只打开原仓库；“复制示例”只复制文本，不会执行命令。
  4. 点击“登记元数据”后，到“能力来源”可以看到一条停用的 external:* 记录。
  5. 当前版本不允许启用或执行这种记录。真正接入必须等版本锁定、目录隔离、网络默认关闭、取消与审计都完成。
关于 WCP：目前没有一个与本项目需求对应、可统一采用的“WCP”标准。这里按可核验的 Agent Skills 与 Model Context Protocol（MCP）分别管理，不用相似缩写冒充兼容性。

创建技能包

  1. 先在“能力来源”确认需要组合的 Skill 都已启用。
  2. 切到“技能包”，填写名称、说明和分类。
  3. 每行或用逗号填写一个 Skill ID；保存时服务会去重并拒绝未知或停用 ID。
  4. 回到工作台“流程”页，点击技能包即可选中整组 Skill；你仍能逐项取消或补选。

创建后台分类

“分类”页支持名称、颜色、范围与说明。内置分类只读；自定义分类保存到本地工作目录 `.ainovel/categories.json`。删除分类不会自动改写已有能力或技能包记录，避免静默改变历史数据。

完整协议见 CAPABILITY_PROTOCOL.md，接口见 API.md。

故障排查

现象原因处理
Pages 显示“当前未连接后端”公开域名正常；只是默认 Pages 部署没有同时运行 Go API本地项目和浏览器 BYOK 可继续使用；Skill 等服务端能力需启动兼容后端
Pages 保存 API 返回 405仍在使用修复前的缓存脚本强制刷新或清除该站点缓存；v0.2.5 保存配置不会请求 /api/config
模型测试 401Key 无效或未加载检查环境变量/后台配置并重启服务
模型测试 404Base URL、接口协议或 Model 不匹配先确认协议，再检查自动补全后的接口类型和模型 ID；完整端点也可直接填写
返回成功但没有文字接口响应结构与所选协议不一致在“高级网络适配”切换 Chat Completions、Responses、Anthropic 或 Ollama
本地 Ollama 无法从 Pages 访问未开放 CORS，或 HTTPS 页面访问 HTTP 接口被混合内容策略拦截改用本地工作台，或给 Ollama 配置允许来源的 HTTPS 反向代理；鉴权选择“无鉴权”
浏览器报 CORS目标接口没有允许当前 Pages 域名或必要请求头换用明确支持浏览器跨域的接口，或改用同源 Go 后端；前端不能代替目标服务放开 CORS
项目消失浏览器站点数据被清除在“我的”页检查存储状态，导入最近的 v5 项目备份；以后定期导出
Prompt Skill 修改丢失换了域名、浏览器或清除了当前 origin 的 localStorage从 Prompt Skill 备份导入，或导入带覆盖值的项目 v5 备份
在浏览器编辑后端文件没变化浏览器和 Go 后端是两套存储，不做静默双向同步这是数据边界；使用项目操作台显式导入，导出 v5 包迁移浏览器内容
上下文预算一直很小普通助手只取当前选区或正文末尾 1000 字，并叠加所选 Prompt Skill、项目和记忆这是本次请求估算，不是整个项目总字数；需要更多材料时使用“流程”显式选择上下文
旧候选不能替换生成期间正文已变化这是坐标保护；复制候选并手动确认位置
历史候选显示“只读”当前打开的不是生成候选时的项目/文档，或记录来自未保存目标坐标的旧版本返回产生候选的原文档再打开历史；不能定位的旧记录只能复制或整理为记忆
公开目录登记后仍不能运行这是预期安全边界，目录只保存停用元数据查看来源与权限；不要把第三方参考服务器当成已完成的内置沙箱
