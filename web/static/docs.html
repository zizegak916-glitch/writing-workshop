从打开 Pages，到建立自己的写作方法。

不需要先懂 API、Docker 或 Skill。下面先给出能照着点击的 Pages 全流程，再解释真实网文指导、提示词、记忆与自部署增强。

先理解：Pages 产品与可选本地服务

GitHub Pages · 正式在线版

这是项目当前对外发布的真实 HTTPS 站点，不是临时预览。可以建立浏览器本地项目、编辑、导入导出，并使用保存在当前浏览器中的 BYOK 自定义 API。目标接口必须允许此 Pages 域名跨域访问。

可选本地服务

需要服务端密钥保管、后端 Skill、SSE、中断、Go 语料分析或后端项目导入时，再运行仓库自带的原生 Go 服务。它不是外部社区提供的后台；浏览器不会把每次编辑静默镜像到后端。

托管方式不等于功能真假：Pages 的浏览器 BYOK 可直接发起模型请求；默认工作流未同时部署 Go API，所以后端 Skill、项目同步和 SSE 仍不可用。GitHub Pages 与 OpenAI Sites 是独立托管方式。

Pages 完整教程：第一次从零走通

入口只有一个：打开写作工作台。项目和设置默认属于当前浏览器，不需要注册站内账号，也不会自动同步到其他设备。

路线一建立项目并完成一次 AI 写作 路线二让真实网文长期指导写作 路线三把结果整理成可控记忆
01

建立项目与第一章

  1. 点击顶部 ＋，填写项目名、题材和简介。
  2. 打开“章节”，新建第一章；正文写在中央编辑区。
  3. 进入“大纲”资料栏：最上方“世界观与硬设定”可直接打开、编辑和保存；剧情路线放其下方的大纲，二者不会计入章节。
  4. 人物稳定事实放“人物”，临时资料和考据放“笔记”。
  5. 第一次重要编辑完成后，点击顶部下载按钮导出 v6 项目备份。

自动保存写入当前域名的浏览器数据库。清除站点数据、换域名或换浏览器前，必须先导出。

02

配置自己的模型接口

  1. 进入“设置 → API”。
  2. 选择服务商；CPA、中转、自建或兼容接口选“自定义”。
  3. 填写实际模型 ID、Base URL 和 Key；无密钥接口选择“无鉴权”。
  4. 明确接口是 Chat Completions、Responses、Anthropic Messages 还是 Ollama Chat；CPA 的 Codex / Responses 路线不要误选成 Chat。
  5. 如果真实 Base URL 是 http://，另填自己的“HTTPS 桥地址”和“桥令牌”。
  6. 点“预览实际请求”，核对浏览器地址、真实上游地址和请求体，再点“测试”。

测试区会保留两个最终 URL、协议、失败阶段、HTTP 状态和浏览器原始错误。只有确实没有收到 HTTP 响应时，才继续排查预检、重定向、混合内容、CORS 或连接问题。

03

完成一次可检查的 AI 写作

  1. 在 AI 面板选择“智能长篇、当前文档、当前选区或全书原文”阅读范围。
  2. 核对状态栏是否显示“设定/大纲已同步”。资料超过 3 万字符时先点“更新全书记忆”；系统会先分块读完世界观、大纲和人物卡，再逐章读取正文。
  3. 选择“润色、续写、改写、对白、节奏”等功能。
  4. 看上下文预算，在“补充指令”写清本次任务，再生成。
  5. 候选出来后选择替换、插入、追加、复制或记入记忆。

每次写作请求都有项目事实包。资料较短时发送世界观、大纲和人物卡原文；超长时使用已经完整分块读取的项目资料记忆。修改资料后旧记忆会立即显示待更新。

04

导入真实网文并本地完整分析

  1. 进入“流程 → 真实网文指导库”。
  2. 选择你有权分析的 TXT、Markdown 或 DOCX，勾选权限确认。
  3. 点击“本地完整分析”。
  4. 先看编码、清洗行数、正文保留率与章节识别，再看综合总结和指导卡。

下载版 TXT 会自动尝试 UTF-8、GB18030/GBK、Big5 与 UTF-16，并先剔除网站广告、投票/更新说明、HTML、重复章名和明显乱码。原文只停留在本次页面内存，档案不保存原文。

05

选择是否让 AI 深析

  1. 本地分析完成后，先检查当前模型配置。
  2. 只有需要补充人物行动、对白功能、信息释放和场景推进判断时，才点击“AI 深度分析”。
  3. 检查 AI 总结、指导卡和“不确定项”；推断不能当成来源事实。

这一步只发送不超过约 18,000 字的分层抽样，覆盖开头、中段、结尾、对白密集段和若干章末；不会自动发送整本小说。

06

让指导卡在写作时真正生效

  1. 保持需要使用的档案为启用状态。
  2. 回到写作功能，照常选择润色、续写、对白或节奏。
  3. 系统只调用与当前 Prompt Skill 有关的卡片；关闭档案后，它不再进入新请求。
  4. 当前要求、项目事实、人物逻辑和原文声音永远高于指导卡。

真实网文的作用不止是改提示词。启用的档案会持续指导实际写作，同时保留适用范围、证据和例外，避免把统计值当写作配额。

07

需要时再修改 Prompt Skill

  1. 在指导库勾选目标 Skill，生成提示词候选。
  2. 优先选择“修改现有指导块”；首次加入可以“追加”；只有准备好完整新提示词时才用“完整替换”。
  3. 在完整预览里手工修改，或主动让当前模型协助修改。
  4. 确认应用后才生效；使用回退可恢复应用前的完整提示词。

不要把来源专名、人物、桥段、句子或固定段长写进提示词。提示词应保留语义、条件、例外和适用场景。

08

把真正长期有效的结果记入记忆

手工内容、写作候选、快捷工具、流程候选、语料总结、单张指导卡和提示词候选都能进入同一记忆表单。保存前编辑标题、分类、来源、项目范围和正文；一次性命令不要当长期记忆。

Pages 记忆进入浏览器 AI 请求。自部署时明确勾选“同时写入 Go 后台记忆”，浏览器会记录该后台条目的 ID；以后再次勾选保存会更新同一条，删除浏览器条目也会删除已关联的后台条目。后台管理页的独立改动不会反向覆盖浏览器。

09

结束这一轮：检查历史并备份

  1. 在“历史”查看候选和写入前快照。
  2. 删除或停用冲突、过时、重复记忆。
  3. 导出 v6 项目包；它包含项目资料、记忆、候选快照、Prompt Skill 覆盖值和语料分析档案，但不包含导入语料原文。

完整可打印教程也保存在仓库的 USER_GUIDE.md。

自部署启动

路线 0：无需安装，继续使用 Pages

打开 Writing Workshop 工作台，新建项目即可编辑。无需安装 Go 或 Docker。由于项目数据属于当前 github.io 域名的浏览器存储，请定期使用顶部导出或项目操作台下载备份。

路线 A：直接运行发布包（Linux VM 推荐）

从 Releases 下载与机器匹配的包：旧虚拟机选择文件名带 _go1.21 的兼容版，新环境选择 _go1.25 版。两者功能相同，解压后运行：

chmod +x writing-workshop
./writing-workshop serve --demo --port 8080

两类发布包均使用 CGO_ENABLED=0 静态构建，不要求虚拟机预装 Go。只有修改并从源码编译引擎时才需要 Go 工具链。

路线 B：Docker

需要安装 Git 与 Docker Desktop。复制下面四行命令：

git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
docker compose up --build

# 浏览器打开
http://127.0.0.1:8080/app.html

Docker 默认使用 Go 1.25.12 构建；需要兼容线时可运行 docker build --build-arg GO_VERSION=1.21.13 -t writing-workshop:go121 .。宿主机只需要 Docker。

第一次会以无密钥 Demo 模式启动。看到工作台后，点击“设置 → API”配置模型；也可以先不配，验证本地项目和内置能力链路。服务端项目、规则和后端 Skill 管理位于同一地址下的 本地服务控制台。

路线 C：直接运行源码

同一套源码同时支持 Go 1.21.13 兼容线与 Go 1.25.12 新版线；CI 两边都测试，并禁止自动切换工具链：

git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
GOTOOLCHAIN=local CGO_ENABLED=0 go build -o writing-workshop ./cmd/writing-workshop
./writing-workshop serve --demo --port 8080

默认只监听 127.0.0.1，这是为了避免把作品与密钥意外暴露到局域网。如确实需要容器或局域网访问，再显式加 --host 0.0.0.0，并自行配置反向代理鉴权。

确认服务健康

curl http://127.0.0.1:8080/api/health
# 预期：{"mode":"demo","status":"ok"}

建立第一个项目

点击顶部 ＋填写项目名称添加第一章建立人物卡/笔记开始写作
  1. 在工作台顶部点击 ＋，填写项目名、题材与简介；已有自定义分类时可同时多选分类。
  2. 左侧切到“章节”，点击“添加章节”，输入标题。
  3. 切到“人物”，录入姓名、定位、描述与角色弧线；临时考据、场景材料和会议记录可放到“笔记”。
  4. 在中间编辑区写作。自动保存开启时，数据写入浏览器 IndexedDB；点击顶部保存可以立即保存。
  5. 第一次重要编辑后，点击顶部下载图标导出项目备份。项目包版本 6 包含项目、章节、大纲、人物、笔记、记忆、当前项目的 AI 候选与恢复快照、自定义分类、Prompt Skill 覆盖值和语料统计档案；不包含导入语料原文。
本地优先：Pages 正式在线版与连接可选本地服务时都可以使用浏览器数据库。清除浏览器站点数据会删除这部分内容，因此长期项目务必定期导出。

工作台各区域做什么

区域用途常用操作
顶部栏项目切换、统计、全局设置新建、设置、导出、保存；检测到同源 Go 服务时才显示“服务”
左侧资料栏项目结构与设定大纲、章节、人物、笔记
中央编辑区唯一正文工作面格式、专注、预览、快速 AI、导出
右侧 AI 区任务、上下文预算与候选助手、对比、记忆、历史、流程；固定请求栏显示本次预算
本地服务控制台（仅自部署）可选服务端配置与调试Provider、URL、Key、服务端项目、规则、后端 Skill、外部能力目录、API 测试

桌面端右侧的能力目录独立滚动，底部“补充指令 / 上下文预算 / 开始生成”请求栏保持可见；切换到对比、记忆、历史或流程时会隐藏，返回“助手”后恢复。手机端会把资料栏和 AI 区折叠到底部导航，预算卡随 AI 内容正常滚动，避免挡住底部导航。正文仍是默认首屏，不会把桌面三栏硬挤进窄屏。

项目操作台

点击顶部项目名进入“我的项目”。搜索框会匹配项目名、类型和自定义分类；分类下拉可进一步筛选。每个项目提供重命名、复制、分类、单独导出和删除。删除会明确列出连带删除的大纲、人物、章节、笔记与记忆并再次确认，不提供无确认批量删除。

“分类管理”创建浏览器本地分类并可修改名称、范围和颜色；项目和记忆分类都可自定义。它们保存在当前站点的浏览器存储，不会自动覆盖本地服务中的后端能力分类。

从自部署后端导入

先用 Docker 或源码启动 Go 后端，再在项目操作台点击“从自部署后端导入”。工作台会读取后端现有项目、章节和人物，建立一个新的浏览器项目副本。之后的浏览器编辑仍保存在 IndexedDB，不会静默覆盖后端资料；需要再次迁移时重新显式导入并核对。

完成一次 AI 写作流程

描述任务选择上下文组合能力生成候选确认写入
  1. 描述这一次任务。例如“检查这段对话的动机断点”，不要写成永久项目规则。
  2. 核对实际上下文。普通助手统一注入项目正式事实包；“流程”中的当前选区/正文、项目设定、大纲、人物卡、项目笔记、记忆仍可单独开关，其中大纲默认勾选。固定请求栏显示估算 token、当前模型上限和百分比。
  3. 选择功能与 Skill。“模式”里的功能卡决定本次隐形使用哪个浏览器 Prompt Skill；“流程”里还可逐项勾选多个后端 Skill，或一键应用技能包。“已选 N 项”会明确显示后端组合。
  4. 点击生成候选。本地后端通过 POST /api/run 返回 SSE 事件；运行中可以中断。
  5. 检查后再决定去向。候选可复制、替换运行时选区、插入光标或追加到正文。普通、快捷、多模型、降 AI 与递归创作都会绑定生成时文档；跨文档应用会被阻止，替换时还会检查正文是否已变化。
  6. 记忆另行确认。“整理为记忆”只把候选放入记忆编辑框，仍需再次保存；不会和正文写入捆绑。
可恢复：流程历史保留完整候选；发生正文写入时还会记录写入前快照。恢复不会自动保存章节，你仍有最后一次确认机会。

导入、导出与备份

导入正文与项目资料

在“我的项目 → 导入项目”选择 Markdown、TXT 或 DOCX。预览会把每个文件分流到正文章节、大纲、世界观或笔记；分类错误可以当场修改。

导出当前正文

编辑工具栏的“导出”用于保存正在编辑的章节，适合送审、分享或进入其他排版工具。

导出完整项目

顶部下载按钮或项目操作台“导出”会先保存当前编辑，再打包项目、章节、大纲、人物、笔记、记忆、本项目候选/恢复快照、自定义分类、已修改的 Prompt Skill 和语料统计。长期创作建议每个重要阶段保存一份带日期的 v6 备份。

增量资料

新增资料应按文件 hash 只处理一次；脚本负责去重和分类，AI 只总结新文件，避免每次重读全库。

同时导入正文、大纲和世界观

  1. 文件名尽量包含用途，例如 作品名_正文.txt、作品名_项目大纲.txt、作品名_世界观设定.docx。带 WRITING_WORKSHOP_IMPORT_HINT_V1 类型标记的文件会优先服从标记。
  2. 选择文件后先看“资料分流”。本地识别会结合文件内类型标记、文件名和内容特征；每一项右侧都能手动改成正文章节、大纲、世界观或笔记。
  3. 再核对统计：只有正文进入章节数和正文字数；大纲、世界观、笔记不会为了参与 AI 分析而伪装成章节。
  4. 正文标题必须独占一行。支持“序章 白日之后”“第一章 尾水”、阿拉伯数字章名和英文 Chapter；“第23章之后……”或“第一卷后半冲突……”这类大纲句不会触发切章。
  5. “AI 自动分析”只补充明确人物，并在完全没有大纲时生成一份大纲。AI 摘要、章名列表和规划节点永远不会创建、替换或补写正文章节。
验收示例：一份《续人间》大纲、一份世界观母本和含序章至第三章的正文同时导入时，预览与导入结果都应显示“1 份大纲、1 份世界观资料、4 个正文章节”。若本地分类猜错，先在预览中改目标，不需要修改原文件。

如果浏览器提示下载被阻止，请允许当前站点下载文件。若导入失败，先确认文件未加密，并用 UTF-8 保存纯文本或 Markdown。一次最多导入 50 个文件；单文件最多 25 MiB、总计最多 100 MiB。v1–v5 项目包会先迁移到 v6 结构，缺少的新字段使用空值，旧记忆、分类和 Prompt Skill 别名会按已知规则保留；高于 v6 的未知版本会被拒绝。v6 导入在一个事务中写入全部项目记录，并重映射历史候选指向的文档 ID；失败时不会留下半个项目。

浏览器存储不是云盘：工作台会申请持久化存储，并在“我的”页显示占用、配额和是否获批；浏览器仍可能拒绝或在清理站点数据时删除全部内容，所以重要阶段必须导出备份。

把有权分析的真实网文变成长期指导库

进入“流程 → 真实网文指导库”，选择 TXT、Markdown 或 DOCX，并确认你有权处理这些文本。它不会训练模型，也不是具体作者仿写器；分析结果既能校准 Prompt Skill，也能在实际写作时按任务动态指导。

确认权限本地完整分析可选 AI 深析形成指导卡写作时调用
  1. 本地引擎先检测 UTF-8、GB18030/GBK、Big5 或 UTF-16 解码，再剔除网址、下载/正版阅读提示、投票与更新说明、HTML 广告、连续重复章名和明显错码行；档案显示编码、清洗行数和正文保留率，污染过重时自动降级。
  2. 清洗后再识别常见中文/数字/英文章名，并统计段句分位、段中对白、行动与解释、章末信号和重复开句；被剔除的站点内容不会进入统计、AI 抽样或写作指导。
  3. 本地结果直接生成带“适用范围、证据、反例”的指导卡。启用的卡片会按润色、续写、对白、节奏等 Skill 动态进入请求，不需要先改提示词。
  4. 只有点击“AI 深度分析”时，页面才把清洗报告与开头、中段、结尾、对白段、章末等清洗后分层抽样发给已配置模型；AI 还会被要求忽略可能漏过的广告、作者说明、乱码和重复标题。
  5. 提示词工作台支持追加、修改旧指导块和整段替换，预览可手工编辑，也可让 AI 修改；确认后才应用，并保留精确回退快照。
  6. 综合总结、单张指导卡和提示词候选都能记入项目记忆；自部署时也可写入 Go 后台记忆。

Pages

本地分析发生在浏览器；原文不持久化。只有你主动点 AI 深析时，最多约 1.8 万字的分层抽样才会发送到你配置的模型。

自部署

Go 引擎把分析档案写入 .writing-workshop/corpus/index.json，后台记忆写入独立文件；原文仍不保存，优秀外部模型可继续通过适配层参与深析和写作。

真实下载版 TXT 验收：先核对编码、章节数、清洗行数和正文保留率。章节翻倍通常来自目录章名与正文章名重复；现在会合并连续重复标题。正文仍有网址、<!--adv-->、更新求票说明或成片错码时，先停用档案并保留复现文件。

仓库回归会用约 26 万字中文输入模拟全部 58 个已登记 AI 入口，并分别覆盖普通响应与流式响应；另用 5 万字以上项目资料和 50 万字以上正文检查世界观/大纲分块、请求体注入、变更失效、逐章覆盖、阶段合并和未改内容复用。这是功能与协议回归，不代替你所选模型的真实上下文、质量和稳定性测试。

统一记忆：从任何工作位置汇入

记忆入口不局限于“记忆”Tab。普通写作候选、编辑器快捷工具、流程候选、真实网文总结、单张指导卡和提示词候选旁边都有记忆入口；它们先打开同一份可编辑表单，再由你确认保存。

配置 API 与模型

Pages 浏览器 BYOK

  1. 打开工作台右上角“设置 → API”。Pages 不需要进入另一套后台页面。
  2. 常见官方服务可直接选择；中转、自建或本地接口选择“自定义”。已有服务商也可以用 Base URL 覆盖默认地址。
  3. 填写 Base URL 和 Key 后先点“获取模型”，从目标 /v1/models 读取真实模型 ID；不要把页面上的价格/额度倍率（如 0.1x）抄进模型名。也可以手填模型 ID。
  4. 展开“高级网络适配”核对协议。自动模式会从完整路径识别；只填 /v1 时默认按 Chat Completions 发送。CPA 的 Codex / Responses 接口应明确选择 Responses。
  5. 标准 Base URL 由工作台补全路径；非标准完整接口勾选“按填写 URL 原样请求”，避免再次拼接 /chat/completions。
  6. 有 Key 的接口保持“自动”鉴权；无密钥服务选“无鉴权”。兼容层要求特殊字段时，可填写自定义请求头和“请求体覆盖”JSON；值为 null 会删除默认字段，例如删除 max_tokens 后补 max_completion_tokens。
  7. 真实 Base URL 是 http:// 时，展开高级适配，另填自己部署的“HTTPS 桥地址”和独立“桥令牌”；不要把模型 Key 当成桥令牌。
  8. 先点“预览实际请求”，核对浏览器发送地址、真实上游地址、协议、脱敏请求头与请求体；再点“测试”。成功后保存，配置只跟随当前浏览器的当前域名。
405 已处理：Pages 保存与测试不会再 POST 静态 /api/config；只有检测到同源 /api/health 的自部署模式才使用后端配置端点。自定义静态域名也会自动进入浏览器 API 模式。

浏览器直连、请求诊断与密钥边界

Pages BYOK 默认从浏览器直接请求目标 API。目标接口必须允许当前 Pages origin、请求方法和 Authorization / x-api-key / Content-Type 等实际使用的请求头；这些由目标服务决定，Writing Workshop 不能替第三方服务器放开 CORS。使用自己的 HTTPS 兼容桥时，CORS 由桥按 WRITING_WORKSHOP_ALLOWED_ORIGINS 严格放行，再由桥访问白名单上游。

但“请求失败”不等于“网络坏了”。先查看测试区：有 HTTP 状态码，就按上游返回的鉴权、路径、模型或请求体错误处理；显示“请求未获得 HTTP 响应”，才说明浏览器没有拿到可读响应，需要继续检查预检、重定向和连接策略。

Pages 工作台浏览器本地配置自定义 API候选返回

完整自部署工作台仍采用同源 API：浏览器访问自己的 /api/，后端读取密钥并请求模型。兼容桥则只负责把 Pages 的模型请求安全转发到固定目标；二者用途不同。

不要混淆：把 Key、桥令牌和自定义请求头存进当前浏览器是用户主动选择的 BYOK；把凭据硬编码进 Pages 文件、仓库 JavaScript、公开环境变量、Issue 或截图仍然是泄露。兼容桥必须是 HTTPS，真实上游才可以是 HTTP。

Prompt Skill 与后端 Skill

管理功能按钮的内置提示词

工作台的 30 个模式卡片以及“实时灵感、资料搜索”两个独立快捷工具，共对应 32 个浏览器 Prompt Skill。点击“润色”“续写”“人物”等功能时，只改变本次请求所用的 Skill；提示词正文不会塞进编辑器，也不会作为聊天内容展示。

  1. 打开工作台右侧 AI 区，切到“流程”。
  2. 在“组合能力”底部找到“内置 Prompt Skill”，点击“查看与修改”。
  3. 按分类或关键词找到功能。左侧“内置”表示使用仓库默认版本，“已修改”表示当前浏览器有覆盖值。
  4. 在右侧改写提示词并保存。下一次点击该功能生成时立即使用新版本，不需要刷新。
  5. 需要撤销时点击“恢复默认”。“导出/导入”可单独备份；完整项目 v6 备份也会携带覆盖值，导入项目时以合并方式恢复。
存储边界：自定义 Prompt Skill 保存在当前域名的 localStorage，不会上传到 GitHub，也不会自动同步到另一台设备、另一个浏览器或另一个域名。清除站点数据前先导出项目或提示词备份。

实际请求按以下顺序组装：内置/自定义 Prompt Skill → 当前选区或正文 → 输出长度与创意要求 → 项目信息和写作记忆 → 额外指令。普通模式、多模型模式、移动端与六个快捷工具都使用同一份浏览器配置。

自己的 Go 内核，不等于只用自己的轮子

Writing Workshop 用仓库内 Go 内核掌握上下文、工具权限、中断、候选写入和审计边界；模型与外部能力则从小接口进入。当前已经开放 engine.ChatModel、四类协议适配、运行时模型切换和 failover。遇到更成熟的外部引擎或组件，先核对许可证、数据流、错误语义、工具调用和中断契约，再选择复用整机、复用组件或只吸收设计。

兼容底线：外部引擎可以更擅长规划、检索或工具调度，但不能静默改正文、越过工具门、吞掉来源错误，或把未授权语料送出本地边界。没有完成适配和回归测试的项目，只能列为参考，不能写成“已集成”。

Pages 填写 http:// API未配置兼容桥时，HTTPS 页面会在发送前按混合内容策略拦截；这不是断网，POST 不会到达 API改用 API 的 HTTPS 地址、打开自部署工作台，或按上文部署自己的 HTTPS Go 兼容桥；前端本身不能绕过浏览器安全策略
兼容桥返回 401 / 403 / 404桥令牌错误、Pages origin 未允许，或目标别名不在服务端白名单分别核对桥令牌、WRITING_WORKSHOP_ALLOWED_ORIGINS 和目标 JSON；模型 Key 错误通常是上游返回的 401
兼容桥返回 413 / 429 / 502请求过大、超过桥并发限制，或桥无法连接 HTTP 上游收紧长篇上下文或按机器容量调整限制；在桥服务器检查上游地址、端口、防火墙和日志
HUB 等标准地址仍显示发送/预检失败旧配置可能残留目标端不允许的自定义请求头查看诊断中的“自定义请求头”；先清空 HTTP-Referer、X-Route 等非必需项，再按目标站实际白名单逐项添加
本地 Ollama 无法从 Pages 访问未开放 CORS，或 HTTPS 页面访问 HTTP 接口被混合内容策略拦截改用本地工作台，或给 Ollama 配置允许来源的 HTTPS 反向代理；鉴权选择“无鉴权”
浏览器报 CORS目标接口没有允许当前 Pages 域名或必要请求头换用明确支持浏览器跨域的接口，或改用同源 Go 后端；前端不能代替目标服务放开 CORS
项目消失浏览器站点数据被清除在“我的”页检查存储状态，导入最近的 v6 项目备份；以后定期导出
旧测试项目里大纲/世界观仍在章节，或出现几十字重复章这些记录由修复前的导入器写进了浏览器数据库；更新代码不会擅自删除现有作品确认原文件仍在后删除该次错误导入的测试项目，再用新版“资料分流”重新导入；预览应先显示正确栏位和章节数
Prompt Skill 修改丢失换了域名、浏览器或清除了当前 origin 的 localStorage从 Prompt Skill 备份导入，或导入带覆盖值的项目 v6 备份
在浏览器编辑后端文件没变化浏览器和 Go 后端是两套存储，不做静默双向同步这是数据边界；使用项目操作台显式导入，导出 v6 包迁移浏览器内容
语料导入被拒绝未确认权限、格式不支持、样本不足 200 字或超过大小限制只导入有权分析的 TXT/Markdown/DOCX；单个语料文件不超过 20 MiB
AI 深析提示需要重新选择文件刷新后原文已从页面内存清除，档案没有保存原文重新选择同一授权文件，先做本地完整分析，再主动运行 AI 深析
指导库存在，但写作没有调用档案已停用，或当前 Skill 与卡片适用范围无关启用目标档案，并选择对白、节奏、续写等相符功能；不会把所有卡片塞入每次请求
记忆越来越多，结果反而混乱存在重复、冲突、过时或跨项目记忆检查标题、来源和范围，停用或删除旧项；一次性任务放补充指令，不存长期记忆
上下文预算一直很小普通助手只取当前选区或正文末尾 1000 字，并叠加所选 Prompt Skill、项目和记忆这是本次请求估算，不是整个项目总字数；需要更多材料时使用“流程”显式选择上下文
旧候选不能替换生成期间正文已变化这是坐标保护；复制候选并手动确认位置
历史候选显示“只读”当前打开的不是生成候选时的项目/文档，或记录来自未保存目标坐标的旧版本返回产生候选的原文档再打开历史；不能定位的旧记录只能复制或整理为记忆
公开目录登记后仍不能运行这是预期安全边界，目录只保存停用元数据查看来源与权限；不要把第三方参考服务器当成已完成的内置沙箱
