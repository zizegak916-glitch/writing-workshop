从资料组织到写入确认，工作台把模型最容易越界的地方变成显式控制。

01

上下文包，而不是整库重发

为每次任务勾选正文、项目设定、大纲、人物卡、笔记与记忆。发送前可见字符数和 token 估算。

当前选区人物卡项目笔记历史记忆
02

候选与正文隔离

模型输出先进入候选区。替换、插入、追加和写入记忆各自确认，运行期间正文变更还会触发坐标保护。

AI 候选
不自动覆盖作品
→
作者确认
选择明确去向
03

多项目资料管理

章节、大纲、人物、笔记、规则与记忆在同一个本地工作区组织，支持 Markdown、文本与 DOCX 导入导出。

04

可组合 Skill

能力清单声明来源、版本、步骤、权限、输入与输出。登记链接不会偷偷执行第三方代码。

05

双通道 API

Pages 可把自定义 API 配置留在当前浏览器并直接调用；自部署版则用同源 /api/ 在后端保管密钥。

四步闭环

从意图到正文，没有隐形动作。

每一步都可以暂停、检查和撤回；AI 不会替作者做最后决定。

选择任务

写清这一轮要规划、续写、改写，还是检查。

组装上下文

只勾选当前任务真正需要的资料与能力。

生成候选

流式查看结果，随时中断，正文保持不动。

确认写入

选择替换、插入、追加或整理为记忆。

在线即可写作

Pages 就是完整的浏览器写作产品。

直接打开 GitHub Pages 即可管理项目、编辑、导入导出、使用 Prompt Skill，并在工作台设置里配置浏览器 BYOK。只有服务端密钥托管、后端项目导入和后端 Skill 执行需要可选的自部署服务。

Docker · 60 秒启动无需 API Key
git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
docker compose up --build

# 打开 http://127.0.0.1:8080/app.html
Pages 正式在线版使用真实 HTTPS 公开域名，浏览器本地项目、笔记、编辑、分类和导入导出可直接使用。
可选本地服务需要服务端密钥托管、后端 Skill 或后端资料导入时，再用 Docker 启动。
模型连接模式在工作台“设置 → API”配置 OpenAI 兼容 API、OpenRouter、Anthropic 或 Ollama。
