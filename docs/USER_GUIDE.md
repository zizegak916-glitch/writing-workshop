# Writing Workshop 完整使用教程

这份教程对应公开的 GitHub Pages 工作台，也标出自部署 Go 服务才有的增强能力。Pages 本身就是可以正式使用的浏览器写作产品：项目、章节、人物、笔记、记忆、Prompt Skill、真实网文指导库和项目备份都能直接使用；需要 AI 时，由浏览器调用你明确配置的模型接口。

## 一、先选使用方式

| 你的需求 | 使用方式 | 数据位置 |
|---|---|---|
| 先写作、管理项目、使用 Prompt Skill、导入真实网文做本地分析 | GitHub Pages | 当前域名的浏览器 IndexedDB / localStorage |
| 在 Pages 上直接调用支持浏览器跨域的模型接口 | Pages 浏览器 BYOK | Key 与接口配置保存在当前浏览器 |
| 后端保管 Key、执行后端 Skill、使用 Go 语料 API、后台记忆与 SSE | Docker 或 Go 自部署 | 自己的 `.writing-workshop/` 工作目录 |

公开在线入口：<https://zizegak916-glitch.github.io/writing-workshop/app.html>

Pages 与自部署站点使用不同域名时，浏览器数据不会自动同步。请用 v6 项目包显式迁移，不要把某个域名里看不到项目误判为项目已被删除。

## 二、第一次完成写作

### 1. 建立项目

1. 打开工作台，点击顶部 `＋`。
2. 填写项目名称、题材和简介；分类可以稍后再补。
3. 进入“章节”，新建第一章。
4. 在中央编辑区输入或粘贴正文。
5. 重要改动后手动保存；即使开启自动保存，也建议在阶段结束时导出备份。

大纲放“大纲”，稳定人物事实放“人物”，考据材料、临时场景资料与创作会议记录放“笔记”。不要把所有资料塞进正文，也不要把一次性任务误存成长期记忆。

### 2. 配置模型

不使用 AI 时可以跳过。

1. 打开“设置 → API”。
2. 选择服务商；中转、自建服务或兼容接口选择“自定义”。
3. 填写模型 ID、Base URL 和 Key。
4. 默认可让工作台自动识别协议；必要时在高级设置中明确选择 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 或 Ollama Chat。
5. 无 Key 的接口选择“无鉴权”。需要特殊请求头时填写 JSON。
6. 先测试，确认返回正文后再保存。

如果测试失败：`401` 先查 Key 和鉴权；`404` 先查模型 ID、协议与地址；浏览器直接报网络错误时再查 CORS、HTTPS 混合内容、DNS 或代理。Pages 不能替目标服务器放开跨域权限。

### 3. 选择任务和上下文

1. 在 AI 面板选择阅读范围。默认“智能长篇”使用当前章节完整原文、全书记忆、相邻章节记忆和人工记忆；也可改为当前文档、当前选区或全书原文。
2. 在 AI 面板选择“续写、润色、扩写、改写、对白、节奏”等功能。每个按钮对应一个可查看的 Prompt Skill。
3. 长篇项目首次使用时点击“更新全书记忆”。系统会说明预计模型请求数，经确认后才逐章读取。
4. 查看上下文预算；它表示本次将发送的内容，不是项目总字数。
5. 在“补充指令”写本次要求，例如：“只修对白动作，保留事实、称呼和事件顺序。”
6. 点击生成。

当前要求、正式设定、人物知情边界和原文事实始终高于通用写作经验、语料统计和检测器偏好。上下文不是越多越好：只选和本次任务有关的材料，模型更容易抓住重点。

#### 长篇怎样完成“全书阅读”

“更新全书记忆”不是只选几章，也不是从全书抽样。它按连续原文块读取每一个现有章节：长章先分块压缩，再合并为章节记忆；连续章节再合并为阶段记忆，最后生成包含主线时间轴、人物状态与知识边界、世界规则、伏笔和未决问题的全书记忆。单章分块或全书阶段过多时会继续逐级合并，每次只合并有限数量的连续记录，避免中间摘要本身撑爆一次请求。每一层都作为 `longbook` 来源记录保存在当前项目中，导出项目包时一并带走。

系统给每章记录内容指纹。再次更新时，未修改章节复用已有章节记忆，只重读发生变化的章节；阶段与全书层仍会重新合并，防止旧总结合并不到新状态。原文不写入记忆，只保存压缩结果。

“全书原文”模式仅适合全文确实落在模型容量内的项目。必须先填写或识别上下文上限；正文加系统提示词和输出预留超出上限时，工作台会阻止请求，不会截掉前文后假装读完。分批阅读会产生多次模型费用，开始前必须确认预计请求数；生成后的记忆仍需作者抽查，尤其是矛盾事实、人物知识边界和未兑现伏笔。

### 4. 审阅候选再写入

AI 输出先进入候选区，不会直接覆盖正文。你可以：

- 替换生成时的选区；
- 插入当前光标处；
- 追加到正文末尾；
- 复制到别处比较；
- 单独整理为记忆。

如果生成后正文已改变，旧候选的替换坐标会被拦截。此时复制候选，人工确认位置；不要强行让旧坐标覆盖新正文。发生正文写入时，历史会保存写入前快照，可恢复后重新检查。

## 三、把真实网文变成写作指导

真实网文既可校准提示词，也可成为写作时按任务调用的长期指导来源。它不训练模型，不复制来源作品，也不要求新稿模仿某位作者。

### 1. 导入与本地分析

1. 打开 AI 面板的“流程”。
2. 点击“真实网文指导库”。
3. 选择你有权分析的 TXT、Markdown 或 DOCX；单文件不超过 20 MiB。
4. 勾选权限确认。
5. 点击“本地完整分析”。

下载站提供的 TXT 不必先手工转成 UTF-8。页面会在 UTF-8、GB18030/GBK、Big5 和带 BOM 的 UTF-16 候选中选择更可信的解码结果，然后先清洗网址、下载/正版阅读提示、投票与更新说明、HTML 广告标记、连续重复章名和明显错码行，再进行统计。档案会显示实际采用的编码、编码置信度、清洗行数和正文保留率；保留率过低时会把证据自动降级，不能让污染文本伪装成写作方法。

本地分析会识别常见中文、数字和英文 Chapter 标题，并计算章节数、段句长度分布、段中对白与对白轮次、短段、长句、行动与解释、场景分隔、章末信号和重复开句等。结果不仅显示数字，还会形成综合总结与指导卡。被清除的下载站内容不会进入统计、AI 抽样或写作指导，档案和项目备份也不会保存原文。

大文件若显示只有一章，先查看是否出现“章节识别降级”提示。章节标题需要独占一行；正文中类似“第二章里他说过”的普通句子不会作为标题。统计是证据，不是固定配额：例如“平均段长 57 字”不能被理解成每段都应写 57 字。

### 2. 阅读指导卡

每张指导卡包含四个关键部分：

- **适用范围**：对白、推进、章末、信息释放或其他任务；
- **指令**：可以怎样调整当前写作；
- **证据**：它依据了哪些本地指标或 AI 分析；
- **例外**：什么场景不应机械套用。

档案启用后，润色、续写、对白、节奏等功能只会取与当前 Prompt Skill 有关的卡片。关闭某份档案后，它不再进入新请求，但档案本身仍保留，可重新启用或删除。

### 3. 可选 AI 深度分析

本地统计完成后，可以主动点击“AI 深度分析”。系统会把本地指标、解码清洗报告与不超过约 18,000 字的清洗后分层抽样发给当前模型，样本覆盖开头、四分之一处、中段、四分之三处、结尾、对白较密段与若干章末。提示词会明确要求模型忽略可能漏过的广告、作者说明、网址、乱码和重复标题。

AI 负责补充统计难以判断的部分，例如场景推进、人物行动、对白功能、信息释放和章节收束，并单列不确定项。它不会自动读取整部作品，也不能把推断写成来源事实。没有点击这个按钮时，原文不会发送给模型；刷新页面后，本次页面内的原文和抽样会消失。

### 4. 在写作中使用指导

启用档案后，直接回到普通写作功能即可。调用关系是动态的：

| 当前任务 | 主要调用的指导 |
|---|---|
| 润色、改写、去 AI | 句段组织、重复、解释密度、原文声音保护 |
| 续写、扩写 | 场景推进、行动链、信息释放、章末承接 |
| 对白、角色 | 对白轮次、对白功能、动作伴随、人物差异 |
| 节奏、高潮 | 段句分布、场景切换、长短段组合、收束信号 |
| 分析、校对 | 证据、异常、适用范围与不确定项 |

指导卡的优先级低于当前要求、正式设定、人物逻辑和原文事实。来源之间相互冲突时，应保留分歧，不把多本作品硬揉成一种“标准网文”。

### 5. 怎样验收下载版 TXT

导入后先看档案中的四项：编码是否合理、章节数是否接近目录、清洗行数是否异常、正文保留率是否过低。章节数翻倍通常意味着目录章名和正文章名同时存在；现在连续重复章名会合并。正文中仍出现网站地址、`<!--adv-->`、投票/更新说明或成片“锛、銆、锟斤拷”时，不要启用该档案，先保留文件和复现步骤提交问题。

项目的自动化回归还会用 26 万字级中文输入模拟全部 56 个已登记 AI 入口，同时覆盖普通响应与流式响应；另用 50 万字以上、24 章正文验证逐章分块覆盖、阶段合并和未改章节复用。这些测试只验证任务登记、完整请求传递、协议、覆盖范围和长输出上限，不会冒充真实模型质量评测。模型本身的上下文上限、响应质量和服务稳定性仍以你实际配置的接口为准。

## 四、修改 Prompt Skill

### 直接管理某个功能

1. 打开“流程 → 内置 Prompt Skill → 查看与修改”。
2. 搜索“润色、续写、对白”等功能。
3. 先阅读当前完整提示词，再修改。
4. 保存后，下一次使用该按钮时生效。
5. 可恢复默认，也可单独导入、导出提示词备份。

### 用真实网文生成提示词候选

在指导库中选择目标 Skill 后，有三种处理方式：

| 方式 | 适合情况 | 风险 |
|---|---|---|
| 修改现有指导块 | 已经应用过语料指导，只想刷新这一部分 | 最稳，不碰其他自定义内容 |
| 追加到现有提示词 | 当前提示词没有语料指导，希望保留原文并增加一块 | 多次追加前先检查是否重复 |
| 完整替换 | 已经准备好一份完整新提示词 | 影响最大，必须完整审阅预览 |

候选预览可以手工修改，也可以主动让当前模型协助修改。只有点击确认应用才会写入；应用前会保存完整快照，可以逐 Skill 精确回退。不要把统计阈值写成死规则，也不要把来源专名、人物、桥段或句子写进提示词。

## 五、统一记忆怎样使用

记忆不是只有“记忆 Tab”能添加。当前可从以下位置汇入：

- 手工新增；
- 普通写作候选；
- 编辑器快捷工具结果；
- 流程候选；
- 真实网文综合总结；
- 单张指导卡；
- 提示词候选；
- 自部署 Go 后台管理页。

所有入口都先进入可编辑的记忆表单。保存前检查：

1. **标题**是否能让未来的你看懂；
2. **分类**是人物、世界、情节、文风、研究还是普通笔记；
3. **来源**是否正确保留为 writing、workflow、corpus、prompt 或 manual；
4. **范围**是当前项目还是通用；
5. 内容是否是长期有效事实，而不是“把这段写长一点”之类的一次性命令。

浏览器记忆会进入 Pages 的 AI 请求。自部署时，勾选“同时写入 Go 后台记忆”才会额外写入后端；后台启用项会按项目加入后端写作与改写请求。两边不做静默双向同步，避免后台资料和浏览器草稿互相污染。

## 六、备份、迁移与恢复

### 把正文、大纲与世界观一起导入

1. 进入“我的项目 → 导入项目”，同时选择 TXT、Markdown 或 DOCX。
2. 在导入预览逐项核对“资料分流”。本地识别会先读取文件内类型标记，再结合文件名与内容判断正文章节、大纲、世界观或笔记；任何一项都可以手动改目标。
3. 只让正文计入章节。大纲和世界观即使出现“序章”“第23章”“第一卷”等字样，也应分别进入大纲与世界观栏位。
4. 正文章名需要独占一行，支持“序章 白日之后”“第一章 尾水”、数字章名和英文 Chapter。“第23章之后继续调查”或“第一卷后半冲突”属于普通内容，不会触发切章。
5. AI 自动分析只补充明确人物，并在项目完全没有大纲时生成一份大纲；AI 的章节摘要、标题列表或规划节点不会成为正文。

例如同时导入《续人间》项目大纲、世界观母本和含序章至第三章的正文，正确结果是：1 份大纲、完整世界观、4 个正文章节。预览分类不正确时直接修改下拉项，不需要先改原文件。

项目包 v6 包含项目、章节、大纲、人物、笔记、项目记忆、当前项目的候选与恢复快照、自定义分类、Prompt Skill 覆盖值和语料分析档案；不包含导入的真实网文原文。

建议在以下时点导出：

- 第一次建立完整资料后；
- 每完成一章或一次大修后；
- 大规模修改 Prompt Skill 前；
- 清理浏览器数据、换浏览器、换域名或换设备前；
- 导入旧项目并确认迁移无误后。

导入 v1–v5 项目时会迁移到 v6。导入过程按事务写入，失败不会留下半个项目。`github.io`、自定义域名与 `localhost` 属于不同浏览器数据空间，迁移必须使用导出的项目包。

## 七、自部署增强

低配置 Linux 虚拟机优先从 [Releases](https://github.com/zizegak916-glitch/writing-workshop/releases) 下载带 `_go1.21` 的兼容包；新环境可选择 `_go1.25` 包。两条线功能一致，均为 `CGO_ENABLED=0` 静态构建，不要求机器预装 Go：

```bash
chmod +x writing-workshop
./writing-workshop serve --demo --port 8080
```

Docker：

```bash
git clone https://github.com/zizegak916-glitch/writing-workshop.git
cd writing-workshop
docker compose up --build
```

Docker 默认使用 Go 1.25.12 构建；兼容线可运行 `docker build --build-arg GO_VERSION=1.21.13 -t writing-workshop:go121 .`。宿主机只需 Docker，不需要 Go。

打开：

- 工作台：<http://127.0.0.1:8080/app.html>
- 本地服务控制台：<http://127.0.0.1:8080/admin.html>
- 健康检查：<http://127.0.0.1:8080/api/health>

自部署增加服务端密钥、后端 Skill、SSE、中断、Go 语料 API、后台记忆和后端项目导入。浏览器工作台仍保留候选确认与本地项目边界，不会因为有后端就自动覆盖正文或同步全部数据。

需要修改 Go 引擎本身时再从源码编译。同一源码同时验证 Go 1.21.13 兼容线和 Go 1.25.12 新版线，并使用 `GOTOOLCHAIN=local` 避免自动下载其他工具链后产生“看似兼容”的结果：

```bash
GOTOOLCHAIN=local CGO_ENABLED=0 go build -o writing-workshop ./cmd/writing-workshop
```

仓库自有 Go 内核负责上下文、工具权限、中断、候选写入和数据边界；模型与成熟外部引擎继续通过适配层接入。接入外部能力不意味着放弃其优势，也不允许它绕过作者确认或未授权发送资料。

## 八、常见问题

### 为什么 Pages 提示没有连接后端？

这是正常状态。项目管理、编辑、导入导出、Prompt Skill、本地真实网文分析和浏览器 BYOK 仍可使用；后端 Skill、Go API 和后台记忆需要自部署。

### 为什么导入真实网文后没有影响写作？

确认档案仍为启用状态，并使用与卡片适用范围相符的 Prompt Skill。指导库按任务选择卡片，不会把所有规则塞入每一次请求。

### 为什么 AI 深析按钮不能用？

先在本次页面重新选择原文件并完成本地分析，再检查模型配置。档案只保存指标和指导，不保存原文，所以刷新后不能从档案恢复抽样。

### 为什么提示词修改后换浏览器就没了？

覆盖值保存在当前域名的 localStorage。请导出 Prompt Skill 备份，或导出包含覆盖值的 v6 项目包后再迁移。

### 记忆越多越好吗？

不是。冲突、过时、一次性和重复记忆会争夺上下文。定期删除、停用或改写，保持事实明确、范围正确、来源可追踪。

### 可以导入喜欢的作者并要求完全模仿吗？

不可以。指导库提取聚合结构信号和可解释的写作方法，不复制作者身份、专名、人物、情节、句子或连续表达。需要的是理解作品怎样运转，再让新稿服从自己的设定和人物。

## 九、提交问题时带什么

请在 GitHub Issues 提供：

- Pages / Docker / 源码运行方式；
- 设备、浏览器与版本；
- 可重复的操作步骤；
- 期望结果与实际结果；
- 已脱敏的报错或控制台日志。

不要提交 API Key、完整私稿、未授权网文或含隐私的项目备份。
